一、这次实际完成了什么
1. 保留原有 v1 和压缩包，另建本目录。
2. 覆盖图2的30个、图3的28个、图4的6个产物。
   64个产物对应66个溶质结构分支：F2_E11的endo/exo、F2_E22的两个环氧面异构体分别保留。
   另有一个TMS参比分子。共67个溶质/参比模型，201个固定组成分支。
3. 每个模型在DMSO-d6连续介质中准备三组：
   A. DMSO_00_W00_continuum：0个显式DMSO，0个水；首批3个起始构型。
   B. DMSO_02_W00_primary：2个显式DMSO-d6，0个水；首批4个起始构型。
   C. DMSO_02_W01_trace_water_sensitivity：2个显式DMSO-d6，1个普通H2O；首批7个起始构型。
   共938个首批输入，其中924个为产物模型，14个为TMS。
4. 每个作业包含可读的3D MOL、四列XYZ、ORCA GOAT输入、明确的原子/同位素映射和来源记录。
5. 原子拓扑、产物18O位置、既定立体结构、溶质原子顺序保持与v1一致。
   独立ETKDG起始构象经力场处理后做几何/立体检查；困难结构若需回退，记录回退原因。
   随后加入溶剂：优先测试可行的供氢/受氢接触，同时准备不同朝向。
   这些是起始结构，不是优化后的稳定微溶剂化构象。

二、模型的含义与不能声称的内容
- 显式DMSO-d6中的12个氢位点按D质量保存；水按普通H2(16O)保存。
- 不因合成中使用18O水或过氧化物，就自动把核磁样品残余水设为18O水。
- 不自动把产物OH/NH氢换成D；真实交换状态仍取决于样品与实验条件。
- 2个DMSO是复用51包的计算方案，不是测得的配位数，也不证明足够覆盖完整溶剂壳层。
- 加1个水是独立的含水敏感性模型，不能换算成样品含水量。
- A、B、C不能直接按自由能合并做玻尔兹曼平均。不同立体异构体、盐型、质子化态亦不能混合。
- 298.15 K为暂定温度；实际温度不同，应按真实条件重新建立参数版本。
- 18O质量标记不等于已算出实验18O同位素位移。常规静态屏蔽计算不包含完整振动平均同位素效应。
- 本包没有实验谱图、没有目标产物的DFT结果、没有完成GOAT采样或最终NMR谱。

四、当前可运行范围
本次交付阶段：初始构型生成/核验，以及明确点名的单个GOAT作业执行器。
没有端到端批量提交、GOAT科学验收、微溶剂化DFT和谱图汇总全流程。
不要把这些簇直接塞入v1的普通核磁执行器：否则环境原子可能被错误地算成产物谱峰。

先检查依赖（不会运行量化计算）：
  python scripts/goat_job.py preflight --orca /path/to/orca --xtb /path/to/otool_xtb

只检查指定作业，不启动：
  python scripts/goat_job.py run --job-id F2_E01_rep_R__DMSO__DMSO_02_W00_primary__s01 --orca /path/to/orca --xtb /path/to/otool_xtb --acknowledge-models --dry-run

只有操作者主动去掉--dry-run，才运行该单个作业。必须先在实际计算节点完成依赖和小体系试运行。
本机静态检查：ORCA二进制标记为6.1.1；外部otool_xtb及配套libiomp5md.dll缺失。
未复制/安装外部程序，未更改系统配置，未启动任何ORCA作业。

检查质量映射与产物NMR原子掩码：
  python scripts/mass_handoff.py JOB_DIRECTORY XYZ_FILE
该工具只输出内联坐标片段及原子掩码。它不批准构象，也不是生产DFT输入生成器。
真正的Opt/Freq必须使用验收后的GOAT构象，并按映射在内联坐标恢复18O和D质量。
四列start.xyz特意不携带质量；GOAT初始电子势能面采样与后续质量相关热化学必须区分。

运行工程测试（无量化计算）：
  python -m unittest discover -s tests -v

后续DFT衔接、J基准、多方法参比和产物-only汇总需要在真实GOAT结果上继续实现与验证。
首批3/4/7个起始作业不代表收敛；成功任务数、低能盆地重现、溶剂接触类型覆盖、位移稳定性均需检查。
后续候选上限只作为预算规划保存，没有自动放行或取消作业。
