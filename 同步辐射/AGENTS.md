# Execution contract for Codex on the HPC system

The user requests completion of this structure-based XAS workflow. Setup, read-only platform discovery, local user-space software installation, preparation, numerical checks, ordinary scheduler submissions under the configured resource limits, monitoring, post-processing, and reporting are authorized. Continue autonomously through routine recoverable errors; do not stop after a plan or merely creating inputs.

1. Read README.md, config.json, docs/STRUCTURE_SELECTION.txt and docs/SOFTWARE_SETUP.txt. Preserve the supplied 16 CIFs and verify structure_checksums.json. The user confirms they are optimized Materials Studio/VASP geometries. Original DFT charge/U/magnetic settings are unavailable; do not invent them or repeat DFT by default.
2. Determine Linux architecture, scheduler, queues, account requirements, permitted login-node activity, module commands, network and storage. Use actual site documentation and read-only queries. Fill config.json with observed values. Do not invent a partition/account or assume root access.
3. Install inside this project. Use official pinned FEFF10 source and check its digest. Use existing licensed/allowed working software when configured. If the default GNU build fails, inspect source/build logs and available compilers; any fix must be logged with version and diff. Do not silently replace FEFF10 with Feff8L for XANES.
4. Run software and parser self-tests. Run actual pilot FEFF tasks through the scheduler. A syntax check or mock process is not a physical FEFF run. Zero exit status without usable spectra is failure.
5. Execute the convergence profiles and review actual spectra. Check SCF convergence and core-hole treatment in raw logs, not only final spectra. Automatic radius comparisons cover representative W/Co/Fe sites; they do not validate every physical assumption. If tolerances fail, inspect the cause and extend justified tests within the resource budget. Do not move forward by changing the tolerance solely to pass.
6. Default production scope is core (7 models, all their Co/Fe/W absorbing atoms). Full16 is retained for justified extension, not automatically submitted in addition. Honor scheduler.max_concurrent and time/memory limits. No bulk FEFF work on a login node. Explicit local mode is only for an already allocated compute session.
7. Preserve per-site spectra. Average all intended sites with recorded weights; distinguish representative pilot spectra from full element averages. Use common processing settings. Never shape output to reproduce the old illustrative curves or a desired active-site conclusion.
8. Use structure/adsorbate names, not OCP or applied voltage labels. The data are Calculated FEFF10 spectra. FEFF's self-consistent electronic calculation is not a transfer of VASP's charge density or a constant-potential electrode simulation.
9. Handle transient interruptions using run_result.json, hashes and scheduler state. If a previous job state cannot be queried, do not submit a duplicate array. Before changed input settings, retain the old calculation in an archive/new profile rather than overwrite a live calculation. Record changes.
10. Read real errors and repair their cause; do not fabricate spectra, replace missing jobs with zeros, skip an absorbing element, or label a partial average complete. Partial diagnostic output is allowed only with explicit PARTIAL labels and is not the final deliverable.
11. Finish Larch post-processing and Python visual QA. Inspect panel text, source-data mapping, energy/k units, FT complex parts, WT scales, missing points and fonts. Arial is preferred if installed; disclose the fallback if not available, rather than claiming all fonts are Arial. Use only legally available font files.
12. Deliver raw FEFF inputs/outputs, frozen environment, logs, complete CSV/NPZ, PDF/SVG/PNG, methods/settings, convergence report and a ZIP. Explain numerical/physical limitations and any remaining missing information. Claim completion only for calculations actually run and checked.

Recommended starting command: `bash run_all.sh core auto`. If monitoring must outlive the terminal, use tmux or a permitted lightweight monitoring session. On failure, inspect logs, resolve the issue and resume. Use the configured credentials/environment; do not request passwords or put secrets in files.
